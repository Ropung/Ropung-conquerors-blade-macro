# Conqueror's Blade Macro

실행 수량은 **1세트 = 15개**입니다. 시작 전에 `세트 수`를 지정하면 매 세트 15개 구매→분해를 반복하고 지정한 세트를 모두 완료한 뒤 자동 중지합니다. 예: 3세트는 45개입니다. 기본값은 1세트이며 마지막에 선택한 세트 수를 저장합니다. 진행 표시에서 완료 세트 수를 확인할 수 있습니다. F9 즉시 중지는 유지됩니다. 기존 최대 개수·1회 테스트 옵션 대신 세트 수로 제어합니다.

## 단일 EXE 배포

`build.bat`는 테스트 후 `package_assets.py`로 검토 완료된 15개용 프로필과 필요한 PNG만 모아 EXE에 포함합니다. 백업 이미지·게임 전체 캡처·로그·개인 설정은 포함하지 않습니다. 결과물은 `dist/ConquerorsBladeMacro.exe` 하나입니다.

배포판은 상인 앞에서 `시작`을 누르면 게임 내부 해상도를 감지하고 내장 프로필로 실행합니다. 별도 Python 설치나 사용자 캡처가 필요하지 않습니다. F9로 중지할 수 있으며 기본값은 15개 구매·분해 1회 후 자동 중지입니다. 배포판의 구매 수량은 검토된 15개로 고정합니다. 설정과 로그는 `%LOCALAPPDATA%/ConquerorsBladeMacro/`에 저장합니다.

QHD는 `calibration/profile.json`, FHD는 `calibration/1920x1080/profile.json`을 사용합니다. FHD 프로필은 실제 1920×1080 게임 화면에서 제작·검토한 뒤 빌드해야 지원됩니다. FHD 프로필이 없으면 FHD 실행을 중지합니다. 현재 소스에 FHD 프로필이 없으므로 FHD 실게임 검증과 EXE 빌드는 아직 필요합니다.

현재 구매 흐름은 **마구 상점 → 2페이지 → 버들잎 면갑 항목·구매 버튼 확인 → 새 구매창에서 설정 수량 입력 → 구매 확인**입니다. 구매 전 수량·구매 비용 이미지 및 구매창의 아이템 재검사는 하지 않습니다. 구매 후 인벤토리 대상 수량과 분해 비용·등록 슬롯·완료 팝업 확인은 유지합니다. 아래의 이전 수량·구매 비용 이미지 보정 안내는 현재 구매 흐름에 필수가 아닙니다.

Windows GUI로 파란 **버들잎 면갑** 구매 → 최대 15개 단위 분해를 제어하는 Python 프로젝트입니다. 요구사항 원문은 `PLAN.txt`입니다.

## 현재 상태

GUI, 수량 설정 저장, F6~F9, 작업 스레드, MSS/OpenCV 인식, 화면 보정 도구, 구매·분해 흐름, 오류 중지와 빌드 스크립트를 구현했습니다. **실제 게임 템플릿은 포함되어 있지 않으며 실게임 구매·분해 검증은 미완료입니다.** 즉시 작동하는 완제품으로 취급하지 마세요. 최초 실행과 매 실행 종료 후 실제 입력은 해제됩니다.

공식 약관 및 운영 공지는 자동 게임 제어 봇 사용을 금지합니다. 적용 서버의 정책을 확인하세요. 안티치트 우회·메모리 접근·입력 은폐 기능은 없습니다.

## 설치와 실행 (PowerShell)

기존 설치에서 업데이트했다면 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`를 다시 실행하세요. F/I/ESC 키는 PyDirectInput의 스캔코드/SendInput 방식으로 전송합니다. 마우스 클릭도 SendInput으로 0.12초간 눌렀다 뗍니다. 커서 이동도 SendInput으로 통일하고 이동 후 0.15초 대기한 뒤 클릭합니다. 수량 입력은 기존 PyAutoGUI 방식을 유지합니다. 목표/실제 커서 좌표를 로그에 남깁니다. 이 변경은 실게임에서 F키가 받아들여지는지 별도 확인해야 합니다. [PyDirectInput 공식 설명](https://github.com/learncodebygaming/pydirectinput)

Python **3.12 x64**, Windows 10/11이 필요합니다. 쓰기 가능한 폴더에서 실행하세요.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

수량은 1~20, 기본값 15입니다. `config.json`은 첫 설정 저장 시 생성되며 EXE/소스 폴더에 보관됩니다. `config.example.json`에 기본 설정이 있습니다. 창 제목 기본값은 `컨커러스 블레이드`이며 정확히 일치하는 창이 하나 있어야 합니다.

## 보정

보정 화면은 **① 캡처·보정 → ② 인식 확인 → ③ 동작 테스트 → ④ 최종 검토** 네 탭으로 나뉩니다. 항목 이름 앞의 `클릭 대상`, `확인 이미지 · 클릭 안 함`, `검색 영역 · 클릭 안 함`을 먼저 확인하세요.

인벤토리 화면에서 대상 아이템에 마우스를 올린 뒤 한 번 캡처합니다. 같은 캡처에서 인벤토리 칸의 작은 아이콘을 한 장 저장하고, 툴팁 안의 아이콘·이름·파란 등급은 한 사각형으로 묶어 한 장 저장합니다. 첫 이미지는 후보 위치를 찾고 두 번째 세트 이미지는 실제 아이템인지 확인합니다. 구매 확인 창의 아이콘·이름·파란 등급도 한 사각형에 묶어 한 번 저장합니다.

①에서 게임 화면을 한 번 캡처하고 대상 하나를 드래그한 뒤 `대상 선택 완료 → 검색 범위`를 누릅니다. 같은 화면에 대상 테두리와 노란 검색 범위가 표시됩니다. 클릭 대상은 클릭할 중앙점도 표시합니다. 검색 범위는 대상 전체를 포함하고 같은 모양의 다른 버튼은 가급적 제외하세요. 기본 범위를 그대로 저장할 수도 있습니다. 인벤토리/분해 칸 검색 영역 항목은 이미지 없이 영역만 한 번 저장합니다. 같은 화면의 다음 항목에는 캡처를 재사용하며, 화면 단계가 바뀌면 새 캡처를 요구합니다. 이전 단계로 돌아가면 이전 캡처를 다시 보여주므로 실제 게임 화면이 달라졌다면 재촬영하세요.

②에서는 선택한 이미지의 최소 유사도를 **50~100%**로 지정하고 `이 항목에 기준 적용`으로 저장할 수 있습니다. 새 이미지의 기본값은 90%이며 기존 항목의 값은 유지합니다. 낮추면 다른 물건이나 버튼도 일치할 수 있으므로 실제 화면 인식 결과를 확인하세요. 기준을 변경하면 수동 검토 완료 표시는 해제됩니다. 유사도는 정답 확률이 아닙니다. 인벤토리 아이콘과 분해 칸 이미지는 자동 실행 시 별도로 지정한 인벤토리/슬롯 영역에서 검색합니다.

시작 전 캐릭터를 상인 바로 앞에 두세요. 첫 게임 입력은 F키이며, 상호작용 안내 이미지(`npc_ready`)는 더 이상 저장하거나 인식하지 않습니다. F키 후 마구 상점 메뉴가 인식되어야 진행합니다. 최초에는 상점을 한 번 열어 확인한 뒤 닫고, 인벤토리에 기존 대상이 없는지 검사한 후 구매 흐름을 시작합니다. 상점/인벤토리를 닫을 때도 F 안내 대신 해당 창 표시가 사라졌는지 확인합니다.

별도 상점 툴팁 캡처는 제거했습니다. `shop_target.png`에 버들잎 면갑 아이콘·이름·파란 등급을 함께 포함해 저장하고, 구매 전 이 항목 이미지가 일치해야 진행합니다. 구매 확인과 인벤토리 툴팁도 아이콘·이름·등급을 각 한 장의 세트 이미지로 비교합니다. 기존 분리형 보정은 `buy_target_identity`와 `inventory_target_identity`를 새로 저장해야 합니다. 이전 이미지 파일은 자동 삭제하지 않습니다.

보정 목록은 NPC → NPC 메뉴 → 상점 → 2페이지 → 구매 수량 창 → 인벤토리 → 빈 분해 칸 → 대상 설명 → 분해 등록/비용 → 완료 순서로 정렬됩니다. 기본 `순서대로 전체` 모드에서는 검색 영역도 해당 단계에 함께 표시합니다. 저장하면 다음 항목으로 이동하며, 기존에 저장한 항목은 유지하고 처음 미저장 항목부터 시작합니다. 화면이 바뀌는 단계에서는 안내에 따라 게임 화면을 변경하고 다시 캡처하세요. 이전/다음 버튼으로 항목을 다시 선택할 수 있습니다.

메인 화면의 `게임 해상도`를 실제 게임 해상도와 맞추세요. 기본값은 2560×1440이며 1920×1080, 3440×1440, 3840×2160 등도 선택할 수 있습니다. 테두리 없는 전체 창 모드를 권장하며 일반 창 모드에서도 게임 내부 화면 크기가 선택 해상도와 같으면 캡처할 수 있습니다. `화면 캡처 / 보정`의 캡처 버튼을 누르면 프로그램 창을 숨기고 3초 뒤 게임 화면을 촬영합니다. 그동안 원하는 게임 UI를 표시하세요. 다른 창이 게임을 가리면 가린 화면이 저장될 수 있으므로 결과를 확인하세요.

기존 2560×1440 보정은 `calibration/profile.json`에 유지하고, 다른 해상도는 `calibration/1920x1080/`처럼 별도 폴더에 저장합니다. 해상도를 바꾸면 해당 해상도에서 이미지와 영역을 새로 보정해야 합니다. 기존 이미지를 자동 확대·축소하거나 좌표를 추정하지 않습니다.

1. 수량을 선택합니다. 처음에는 **1개**로 보정하세요.
2. `템플릿` 목록의 각 이름에 해당하는 실제 UI를 캡처·저장합니다. 상점 2페이지의 파란 버들잎 면갑을 사용합니다. 이름/파란 등급은 `shop_`, `buy_`, `inventory_`별로 따로 보정합니다.
3. `quantity_N`은 **전체 수량 필드**, `buy_cost_N`과 `dismantle_cost_N`은 **통화 아이콘·전체 비용 필드**를 포함해 잘라야 합니다. 숫자 일부만 자르면 1과 15 같은 값이 잘못 일치할 수 있습니다. 분해 비용은 계획서의 개당 300을 사용하며 실제 화면이 다르면 실행하지 마세요.
4. `영역`에서 전체 대상 인벤토리와 서로 겹치지 않는 `slot_0`~`slot_14`를 각각 지정합니다. 인벤토리는 슬롯 영역과 겹치면 안 됩니다. 슬롯 템플릿은 빈 슬롯/대상 슬롯 내부의 공통 이미지입니다.
5. 수량별 팝업·비용·아이템 이름·등급 및 영역을 수동 검토한 뒤 검토 완료 표시를 합니다. 템플릿/영역 변경 시 기존 검토 표시는 모두 초기화됩니다.

보정 파일과 PNG는 `calibration/`에 저장됩니다. 기본 검색 범위는 자른 위치 주변 12px입니다. 움직이는 인벤토리 툴팁은 화면 전체에서 이름·등급의 유일한 일치를 찾습니다. 필요하면 `profile.json`의 `roi: [x,y,width,height]`를 실제 캡처에 맞게 수정하세요. 변경 후 반드시 다시 검토하세요. 스케일 변경이나 추정 좌표는 지원하지 않습니다.

## 실행과 중지

실제 입력 실행 중에는 화면 아래에 클릭을 가로채지 않는 진행 표시도 띄웁니다. 게임을 활성화한 채 등록 개수·현재 작업·경과 시간·중지 사유를 볼 수 있습니다.

실행 중에는 진행 표시줄, 현재 단계, 전체 경과 시간, 마지막 진행 이후 시간이 표시됩니다. 대상 등록은 `등록 3/15`처럼 갱신되고, 오류 시 별도 `중지 이유`가 표시됩니다. 같은 아이템 묶음은 이름·등급을 처음 한 번 확인하고 각 고정 칸의 동일 아이콘을 재확인해 등록하며, 등록 후 전체 슬롯 수·인벤토리 잔량·비용을 검사합니다. 일부가 등록된 상태로 분해만 테스트를 다시 시작하면 등록 수 + 인벤토리 잔량이 설정 수량과 일치할 때만 나머지를 등록합니다. 다른 아이콘·모르는 슬롯·위치 변경은 중지합니다.

### 첫 실제 구매·분해 테스트

이미 구매한 아이템만 시험하려면 게임에서 분해 창을 열고 메인 GUI 수량을 보유한 대상 수(최대 15)로 맞추세요. 실제 입력을 체크한 뒤 `기존 아이템 분해만 1회 테스트 (구매 안 함)`을 누릅니다. 수량/비용 확인창에서 진행을 선택하면 3초 후 시작합니다. 분해 칸이 모두 비어 있으면 대상 수량을 확인해 등록하고, 이미 정확한 수량이 등록되어 있으면 슬롯의 대상과 빈 인벤토리를 확인한 뒤 분해합니다. 일부만 등록되어 있거나 다른 아이템/수량/비용이면 중지합니다. 이 테스트는 실제 분해를 실행하며 완료 팝업을 확인한 뒤 끝납니다. F6 전체 흐름과 달리 기존 대상 아이템이 있어도 시작할 수 있고 추가 구매는 하지 않습니다.

GUI의 `1회 테스트 후 자동 중지`는 기본 체크됩니다. 수량을 1로 설정하고, `quantity_1`, `buy_cost_1600`, `dismantle_cost_300`을 실제 화면에서 새로 저장하세요. 대상 인벤토리에 기존 버들잎 면갑이 없어야 합니다. 빈/등록 분해 칸 템플릿은 한 칸 내부만 포함하고, 15개 슬롯 검색 영역은 서로 겹치지 않게 지정해야 합니다. 보정 검토를 완료한 뒤 실제 입력을 체크하고 F6으로 시작하면 1개 구매 → 1개 분해 → 완료 팝업 확인 → 자동 중지합니다. 단순 동작 테스트와 달리 실제 코인과 아이템을 소모합니다. 이상하면 F9로 중지하세요. 성공 확인 후 15개, 20개로 늘려 수량별로 다시 보정·검토할 수 있습니다. 반복 실행은 1회 테스트 체크를 해제해야 하며, 실행 종료 후 체크가 다시 켜집니다.

### 단계별 인식 테스트 (게임 입력 없음)

항목을 선택하면 `저장된 기준 이미지` 미리보기와 파일명·원본 크기가 표시됩니다. `저장 이미지 원본 보기`로 실제 저장한 PNG를 원본 크기로 확인할 수 있습니다. 인벤토리/분해 칸 검색 영역은 PNG 대신 좌표를 표시합니다.

### 단계별 동작 테스트 (실제 키·클릭 1회)

1번은 상인 앞에서 F키를 누르고 NPC 메뉴의 마구 상점 버튼을 클릭해 상점을 여는 단계입니다. 2번은 상점 2페이지 이동입니다. 1번을 실행하기 전에는 NPC 메뉴와 상점을 닫고 상인 앞에서 시작하세요.

1번에는 `NPC 메뉴의 마구 상점 항목`과 `마구 상점이 열린 화면의 고정 표시` 두 이미지가 필요합니다. 후자는 상점을 수동으로 연 뒤 상점 제목처럼 변하지 않는 부분을 저장하세요. 이미지가 부족하면 실행 전 목록을 한국어로 안내하고 첫 미저장 항목을 선택합니다. 동작 테스트 준비/진행/중지 결과는 `logs/macro.log`에도 남습니다.

화면 인식 시간 초과 시 `logs/last_failure.png`에 마지막 게임 화면, `logs/last_failure.json`에 검색 영역·최고 유사도·기준을 저장합니다. 실패 결과는 인식 기준을 자동으로 낮추거나 임의 좌표를 클릭하는 데 사용하지 않습니다. 일반 키 입력은 0.12초간 눌렀다가 떼며, F9 중지 시에도 눌린 키를 해제합니다. 테스트 중 게임 밖을 클릭하거나 다른 창으로 전환하면 중지합니다.

보정 창에서 `동작 테스트에서 실제 키·클릭 허용`을 체크하고 테스트 동작을 선택한 뒤 `선택 동작 1회 실행`을 누릅니다. 3초 안에 게임을 활성화하고 해당 동작의 시작 화면을 준비하세요. F키 → 마구 상점 클릭 → 2페이지 → 아이템 호버/선택 → 구매 수량 창 열기/입력 → 창 닫기 → 인벤토리/분해 창 열기를 각각 독립적으로 시험할 수 있습니다. 동작 후 결과 화면이 돌아오며 다음 동작은 자동 실행하지 않습니다. 해당 동작에 필요한 이미지만 저장되어 있어도 가능하고, F9 중지 단축키가 등록되어 있어야 합니다. 허용 체크는 매 동작 후 해제됩니다. 구매 확정·아이템 등록·분해 실행은 이 동작 테스트에 포함하지 않습니다. 보정 창을 연 동안 F6 자동 반복 시작은 차단됩니다.

### 인식 테스트 사용 방법

보정 창에서 저장한 항목을 고르고 `선택 항목 인식 테스트 (3초 후)`를 누르세요. 보정 창과 메인 창이 잠시 숨겨지면 3초 안에 게임을 활성화하고 해당 화면/툴팁을 띄웁니다. 현재 화면을 새로 캡처하고 결과 창이 돌아옵니다. `현재 단계 전체 인식 테스트`는 같은 단계의 항목들을 한 화면에서 검사합니다. 다른 단계가 미완성이어도 테스트할 수 있습니다.

찾은 위치는 초록 상자, 여러 곳이 일치해 모호한 버튼은 자홍 상자, 기준 미달의 가장 비슷한 위치는 노란 상자로 표시합니다. 결과에는 일치 개수·최고 유사도·판정 기준이 표시됩니다. 유사도는 정답 확률이 아닙니다. 인벤토리/분해 칸 검색 영역은 영역만 표시하며, 대상 이미지 테스트는 저장된 인벤토리/분해 칸 안에서 수행합니다. 잘못된 아이템/화면에서도 실패하는지 함께 확인하세요. 이 테스트는 클릭·키 입력·구매·분해를 수행하거나 보정 완료를 자동 승인하지 않습니다.

- **F6**: 시작. 실제 입력 체크가 꺼져 있으면 현재 화면 인식 진단만 수행합니다.
- **F7**: 일시정지.
- **F10**: 재개. 입력 직전에 일시정지한 경우 이전 좌표를 사용하지 않고 안전 중지할 수 있습니다. 화면을 정리하고 F6으로 다시 시작하세요.
- **F9**: 중지. 콜백에서 중지 이벤트를 직접 설정하며 각 입력 전후/대기 중 확인합니다. 진행 중인 OS 입력 한 번을 되돌리지는 못합니다.
- 마우스를 화면 모서리로 이동하면 PyAutoGUI failsafe로 중지합니다.

실제 입력 실행은 필수 템플릿, 수량별 수동 검토, 게임 창 상태와 단축키 등록이 모두 확인된 경우에만 가능합니다. 시작 전 대상 아이템이 인벤토리에 이미 있으면 중지합니다. 구매 후 정확한 수량과 각 아이템 툴팁을 확인하고, 20개는 15+5로 처리합니다. 슬롯에 모르는 물건이 있거나 수량/비용/완료 팝업이 일치하지 않으면 중지합니다. 모든 대상은 한 화면에 보여야 하며 **스택, 인벤토리 스크롤·다른 탭은 지원하지 않습니다.** 완료는 시간 추정이 아닌 팝업 인식으로 판단합니다.

실게임 1개 → 15개 → 20개 → 반복 테스트는 별도 수행해야 합니다. 구매·분해가 일부 진행된 뒤 중지하면 자동 복구하지 않습니다. 남은 아이템을 수동 확인하고 NPC 앞의 초기 상태로 되돌리세요. 로그는 `logs/macro.log`에 저장되며 최대 2MB×4로 순환합니다.

## 테스트와 EXE

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.bat
```

`dist/ConquerorsBladeMacro.exe`는 Python과 의존성을 포함합니다. 설정·보정·로그는 EXE 옆에 외부 파일로 생성되므로 쓰기 가능한 폴더에 두세요. 소스 실행에서 만든 `calibration/`과 `config.json`을 EXE 옆으로 복사할 수 있습니다. 프로그램은 재실행 시 실제 입력을 항상 해제합니다. Python이 없는 별도 Windows PC에서의 실행 검증은 아직 필요합니다.

테스트는 수량 분할, 설정 저장, 읽기 전용 입력 차단, 중지·일시정지 및 보정 누락을 검증합니다. 모의 입력 테스트는 실제 게임 화면 인식이나 구매·분해 성공을 증명하지 않습니다.
